01为什么需要 Context & Memory

从"每次对话都从零开始"，到"越用越懂你"

想象你有一个助理，每次开口前都会把之前的事全忘了——每次你都得重新介绍自己是谁、在做什么项目、上次讨论到哪了。累不累？

这就是现在绝大多数 AI 的状态。它们很聪明，但没有长期记忆，每一次对话都是一张白纸。而 Plaud 做的事不一样：用户每录一次音、每开一次会，这些内容就在 Plaud 里持续积累。问题是——积累下来的这些内容，怎么才能被 AI 真正用起来？

🧠
这就是 Context & Memory 要解决的事。Context 是"AI 能调取的全部信息"——你在 Plaud 上积累的一切。Memory 是"从中提炼出的核心记忆"——不用翻万字转写，直接拿到最有用的事实。两者合一，让 Agent 真正拥有"用过去的积累帮你做当下的事"的能力。

Sam Altman 说过一句话："Memory 是大模型产品的护城河。" 有记忆的 AI 和没记忆的 AI，用起来完全是两个东西。而 Plaud 的独特优势在于——我们的记忆来源不是聊天记录，而是用户真实工作中的录音。这是别人拿不走的第一手数据。

02一句话分清三个概念

Context、Memory、Retrieval——各管什么

Context & Memory 内部实际上有三个角色。别急着记，先看这张图：

🗄️
数据底座
Context Storage
存放用户在 Plaud 上积累的全部内容——录音转写、AI Summary、Highlight、上传文件、Agent 产出物。什么都不丢。
💎
核心记忆
Memory
从 Context 中提炼出的结构化事实——谁承诺了什么、做了什么决定、关键数据点。不是缩写，是筛选。再加上"你是谁"和"你要我怎么做"的个人画像。
🔍
检索能力
Retrieval
Agent 需要信息时的"搜索引擎"。先从 Memory 中定位相关内容，再按需从 Context 拿全文。Agent 所有的信息都经这一层获取。
📚
打个比方：Context 是图书馆的全部馆藏（什么都有，但翻起来慢）；Memory 是从每本书中画出来的重点卡片（精炼且分好类）；Retrieval 是图书管理员（你说一句话，她就能帮你找到相关的卡片和原书）。Agent 不需要自己翻书——它问管理员就行。

03什么是 Context（上下文）

AI 的全部"知识库"——在 Plaud 上积累的一切，它都能调取

Context 就是 Agent 能看到的全部背景信息。在 Plaud 4.0 中，它以文件系统（File System）的形态组织，让用户和 Agent 都能按"时间"、"事项"、"人物"三个维度浏览和检索。

Context 里装了什么

CONTEXT · 原始采集

录音 & 转写

用户的每一段录音和完整转写文本，带时间戳和说话人标注。这是最原始、最完整的"事实底座"——后续所有 AI 产出都以它为起点。
CONTEXT · AI 产出

Summary & Highlight

AI 自动生成的标准化摘要（Summary 0）和重点标注（Highlight）。4.0 的 Summary 定位是"对录音内容的忠实还原"，强调事实准确而非花哨改写。
CONTEXT · 用户导入

文件 & 文档

用户主动上传的文档、从其他工具导入的资料。不限于音频——PDF、PPT、图片，任何你想让 AI 知道的东西。
CONTEXT · Agent 产出

Artifact

Agent 在对话中生成的产出物（邮件草稿、分析报告、方案文档等），会被回存到 Context 中，下次对话时可以继续引用。
🗂️
简单说，Context 回答的是："AI 能调取哪些信息？" 答案是——你在 Plaud 上积累的一切。录音、摘要、文件、Agent 的产出，全都在里面。用户录得越多，AI 能力就越强。

04什么是 Memory（记忆）

从万字录音中提炼核心事实 + 认识"你是谁"

一场 60 分钟的会议，转写出来可能上万字。但真正重要的信息可能就几百字——谁承诺了什么、做了什么决定、有哪些关键数据。Memory 就是做这件事的。

Memory 在 Plaud 中有两个组成部分：

💎 Info Extraction（信息提取）

从录音转写中自动提取结构化事实。目前探索中的分类方向包括（非最终标准，仅供参考）：

  • 行动承诺——谁答应了做什么
  • 决策共识——会上定了什么结论
  • 分歧未决——哪些事还没谈拢
  • 关键数据——数字、指标、日期
  • 背景状态——项目进展、人员关系
  • 观点表达——谁对什么事持什么看法
  • ……以及更多
👤 Personalization（个性化）

让 AI 认识你、按你的方式工作。4.0 中对应两个用户可见的入口：

  • About You——你的职业、行业、工作关注点。告诉 AI"我是谁"
  • About Agent——你希望 AI 怎么帮你（比如"会议纪要重点写行动项"、"用英文回复"）。告诉 AI"你该怎么做"

Agent 处理每一个请求时，都会参考这两份设定——所以不同用户拿到的结果是不同的，即使问同一个问题。

🔑
核心原则：事实压缩，而非摘要改写。Memory 只保留原文中明确说过的事实，不做推测、不做延伸。会上说了"deadline 是 7 月 7 号"就记这个；只是隐约提了"七月上旬"，不会自作聪明地精确到某一天。宁可多提取，也不能提错——因为错误的记忆比没有记忆更危险。

05三层架构：存、记、找

从底向上——原始存储 → 信息压缩 → 智能检索

Context OS 三层架构。Storage 存全量数据，Memory 做信息压缩和用户画像，Retrieval 向 Agent 暴露统一检索能力。
Agent 的一切信息获取都走 Retrieval 层，不会直接翻底层数据。

为什么非得分三层？

因为 Agent 的"注意力"是有限的——它不可能一次性看完用户所有的录音转写（可能有几百万字）。分层的意义在于：

1

Storage 保证"不丢"

所有原始内容和 AI 产出完整保存，用户随时能回溯到任何一段录音的原文。

2

Memory 保证"精"

从万字原文中提炼出高密度事实，让 Agent 能快速判断"哪些录音和这个问题相关"。

3

Retrieval 保证"快"

先用 Memory 缩小范围，再按需从 Storage 拿全文。Agent 既不遗漏，也不被淹没。

06Agent 怎么用它们干活

一个真实的例子——从用户提问到准确回答的全过程

🗣️
用户在 Plaud Ask 里问："上周和客户的会上，他们对定价有什么反馈？"
🗣️ 用户提问
→
🧠 Agent 理解意图
→
💎 Memory 定位
→
🗄️ Context 取全文
→
✅ 有据可依的回答
1

Agent 理解你要什么

关键信息是"上周"、"客户会议"、"定价"、"反馈"。Agent 通过 Retrieval 发起搜索。

2

Retrieval 调 Memory 定位

Memory 中有结构化的事实记录。搜索到：上周三的客户会议中，有 3 条和"定价"相关的事实——一条客户反对意见、一条协商让步、一条最终共识。快速锁定了相关录音。

3

按需从 Context 取全文

如果 Memory 的精华不够回答（比如用户想听原话），Retrieval 进一步从 Storage 中加载那段录音对应的转写全文，拿到上下文细节。

4

组织有据可依的回答

Agent 基于定位到的事实和原文，给出一个有来源可追溯的回答，而不是凭空编造。"根据 5 月 28 日与 Acme 的会议记录，客户 VP 提出……"

这就是三层配合的核心价值：Memory 帮 Agent "快速找到在哪"，Context 提供"完整的是什么"，Retrieval 把两者串起来。

一些更高级的用法

跨会议追踪
"定价方案从上月到现在改了几版？每次改了什么？"
Agent 搜索所有录音中涉及"定价"的 Memory 条目，按时间线梳理出变化脉络——不再需要用户自己翻三四个文件。
个性化输出
"帮我把今天的会整理一下。"
Agent 读过你的 About You（产品经理）和 About Agent（侧重行动项），自动按你的偏好调整输出结构，而不是给一个通用版。
Folder 范围限定
在某个项目文件夹下打开 Ask，提问。
Agent 自动把搜索范围限定在这个文件夹内——不会被不相关的录音干扰，回答更精准。
Artifact 回存
"帮我把上次整理的竞品分析更新一下。"
上次 Agent 生成的分析报告已存回 Context。这次直接在上次的基础上更新，而不是从零开始。

07用户看到什么、能做什么

用户不需要理解架构，只需感受到"这个 AI 越来越懂我"

三层架构是内部实现。用户看到的是简单清晰的几个触点：

① 设置 → Personalization

ABOUT YOU

个人资料 + 补充说明

复用 Onboarding 收集的信息（职业、行业等），加一个"补充说明"文本框，让用户自由补充 AI 该知道的事。可查看，可编辑。
ABOUT AGENT

AI 个性化指令

一个单文本框，替代 3.0 的多个碎片输入（Content Focus、Custom Instruction）。用户用自然语言写"你该怎么帮我"。
MEMORY 待定

记忆管理

用户能看到 AI 从录音中"记住了什么"，并进行查看和管理。该入口是否在 MVP/Beta 中开放尚在讨论。

② Ask 对话——直接用，无需配置

用户在 Ask 里正常提问，Agent 会自动调取 Context 和 Memory。不需要手动选择"从哪个录音里找"。

③ 文件系统——三个维度浏览

4.0 的文件系统让用户按"时间"、"事项/项目"、"人物"三个维度组织和浏览自己的录音与产出，也是 Agent 搜索的底层结构。

④ 你的数据，你控制

🔒
可见可编辑：About You 和 About Agent 的内容你随时能看能改。私密优先：所有 Context 和 Memory 默认只有你自己能看到。——这些是和竞品做差异化的关键体验点。

08和竞品有何不同

记忆能力正在成为 AI 产品的核心战场

📌 对外口径建议：Plaud 的 Context & Memory 和 ChatGPT 的 Memory、Notion AI 的 Knowledge 等处在同一个赛道，但 Plaud 有独家优势——我们有用户的第一手录音数据，这是别家拿不到的信息源。
维度行业通行做法Plaud 的做法
记忆来源 只记 AI 对话本身——你和 ChatGPT 聊了什么，它记住什么。用户不主动告诉 AI，它就不知道。 以录音和真实工作场景为第一手来源。每录一次音就自动积累记忆，不需要用户"告诉"AI。
记忆粒度 大多只做"偏好记忆"——记住你喜欢什么格式、什么语言。本质是 key-value 配置。 事实级结构化提取——10 大分类，从行动承诺到决策共识到关键数据。不是配置，是知识库。
记忆规模 通常有明确上限（如 ChatGPT 限制几千字）。超出部分被遗忘或需手动管理。 理论上无上限——录了多少就存多少，Memory 做压缩，Retrieval 做检索。不靠"删旧的"来腾空间。
跨会话 大多数产品的记忆是单次对话级别。换个对话窗口，上下文就断了。 跨会议、跨时间线——能把不同日期、不同会议里关于同一话题的讨论串在一起。
透明度 用户通常不知道 AI"记住了什么"。记忆是黑盒。 可见可编辑——About You / About Agent 让用户能直接看到和修改 AI 对自己的认知。记忆管理入口是否开放尚在讨论。
数据壁垒 AI 记忆和平台数据弱关联。换个工具，数据从头来。 基于 Plaud 独有的录音→转写→提取→记忆全链路，用户在别处拿不到这些积累。用得越久，越难离开。

一句话差异：别人的 AI 记住的是"你跟它聊了什么"，Plaud 记住的是"你在真实工作中发生了什么"。

09一句话记住

Context 存下你在 Plaud 上积累的一切，Memory 从中提炼出最有用的事实和你的个人画像，Retrieval 让 Agent 能快速调取所需。三者合一，让 Plaud 从"会转写的工具"变成"真正记住你工作的 AI 伙伴"。

用户每多录一次音，AI 就多懂他一分。这件事靠的不是某一个功能，而是 Context & Memory 作为整个产品的底层基础设施在持续运转。

录音即积累 事实级提取 跨会话关联 越用越懂你 可见可控 数据护城河

10名词小词典

对外沟通时，这几个词这样解释最稳妥

Context（上下文）
Agent 可调取的全部信息——你的录音、转写、摘要、文件、Agent 产出。用得越多，积累越深。
Memory（记忆）
从 Context 中提炼出的结构化事实 + 个人画像。不是缩写，是 AI 经过筛选和分类后的核心知识。
Info Extraction（信息提取）
自动从录音中提取结构化事实的技术。10 大分类覆盖行动、决策、数据等。Memory 的核心引擎。
Retrieval（检索）
Agent 获取信息的能力层。先搜 Memory 定位，再按需从 Context 拿全文。Agent 一切的"眼睛"。
About You
设置中的个人信息入口。你的职业、行业、关注点。让 AI 知道"你是谁"。可查看，可编辑。
About Agent
设置中的 AI 指令入口。你对 AI 的个性化要求。让 AI 知道"你要我怎么做"。一个文本框，自然语言。
Summary（标准化摘要）
AI 对录音内容的忠实还原。4.0 定位为"事实底座"——不花哨，但准确，给下游 Memory 和 Agent 提供数据起点。
Context OS
Context & Memory 的内部团队/系统名。包含 Storage、Memory、Retrieval 三个模块。对外不用这个名字。
